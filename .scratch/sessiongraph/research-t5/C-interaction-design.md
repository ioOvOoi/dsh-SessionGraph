## 设计约束（来自已定决策）

1. **无系统弹窗**：图谱内气泡/操作条不算系统弹窗，但必须轻量、不遮挡核心内容
2. **点击原子 = 定位跳转**：现状已实现（scrollToKey + 金环闪烁），不能破坏
3. **B1 遮蔽方案**：跳转时对被放弃分支段执行 compaction 式 replace，旧分支不进模型上下文
4. **细节面板已否决**：不要弹出窗，要和对话融为一体
5. **Obsidian 式**：边常显、灰阶节点、跟随主题
6. **收起窄条**：已实现 SlimOverlay，右下角浮层

## 设计任务 1：确认交互（切枝触发方式）

**现状**：点击原子节点 = 定位跳转（金环闪烁），无任何确认。
**B1 要求**：切枝是破坏性操作（旧分支被遮蔽，影响模型上下文），需要确认。

### 候选方案

#### 方案 A：单击定位、双击切枝

**交互**：
- 单击：只定位跳转（现状不变）
- 双击：在节点旁弹出小型确认气泡「切到这里继续」+ 取消

**优点**：
- 完全不改变现有交互逻辑，单击仍定位
- 双击是明确的「特殊操作」信号，误触风险低
- 演示时可口头说明「双击切枝」

**缺点**：
- 双击在 SVG 图谱上视觉反馈不如 Web 原生控件明显
- 用户可能忘记「单击=定位、双击=切枝」的区分
- 演示时需要口头解释，不够直观

**误触风险**：低（双击阈值约 300ms，距离阈值 4px）

---

#### 方案 B：单击 + 节点旁确认气泡

**交互**：
- 单击节点：先执行定位跳转（金环闪烁）
- 同时在节点旁弹出小型气泡（不遮挡节点本身）：
  ```
  ┌─────────────────────┐
  │ 切到这里继续  ✕      │
  └─────────────────────┘
  ```
- 气泡自动消失条件：3 秒无操作 / 点击其他节点 / 点击空白区域

**优点**：
- 一步到位，单击同时完成「定位 + 确认入口」
- 气泡嵌入图谱，不违背「无系统弹窗」原则
- 演示流程最顺畅：点击 → 看到气泡 → 确认切枝
- 误触可撤销（点取消或 3 秒自动消失）

**缺点**：
- 气泡位置计算复杂（节点在边缘时需要智能翻转方向）
- 可能遮挡相邻节点（尤其工具簇密集区域）

**误触风险**：中（单击后必须主动点「切到这里继续」才算切枝）

---

#### 方案 C：修饰键 + 点击

**交互**：
- 普通点击：定位跳转（现状不变）
- Shift + 点击：直接执行切枝（无二次确认）

**优点**：
- 修饰键是「特殊操作」的通用信号
- 不改变现有交互，完全向后兼容
- 实现最简单，无额外 UI 元素

**缺点**：
- Shift 是隐藏操作，用户不知道就永远发现不了
- 演示时难以展示（观众看不到键盘操作）
- 无二次确认，一旦 Shift+点击就直接切枝

**误触风险**：低（需要同时按 Shift）

---

### 推荐：方案 B（单击 + 节点旁确认气泡）

**理由**：
1. **演示最优**：观众能直观看到「点击 → 气泡 → 确认」的完整流程
2. **符合无弹窗原则**：气泡是图谱内的轻量元素，不是系统弹窗
3. **误触可逆**：3 秒自动消失 + 可点取消，比双击或修饰键更安全
4. **现状兼容**：单击仍执行定位跳转，不破坏现有体验

**实现要点**：
- 气泡位置：优先向右下方弹出；若节点在右侧 20% 区域，翻转到左下方
- 气泡样式：圆角 8px、背景 `var(--dsw-specific-sidebar-fill)`、阴影 `0 2px 8px rgba(0,0,0,.15)`
- 气泡内容：「切到这里继续」文字 + 右上角 ✕ 按钮
- 动画：fade-in 0.15s + scale-up 0.15s

## 设计任务 2：遮蔽态表现

**B1 定义**：被放弃分支段在图谱上显示为「已折叠/被遮蔽」，摘要保留旧分支信息。

### 候选方案

#### 方案 A：灰显 + 折叠为摘要节点

**表现**：
- 被遮蔽的节点整体降低 opacity 到 0.3，颜色变为浅灰
- 遮蔽段折叠为一个「摘要节点」（类似现有的 turn-summary 节点）
- 摘要内容：`N 条消息 · 首尾缩略`
- 鼠标悬停显示完整摘要 tooltip

**与现有折叠共存**：
- 遮蔽段折叠态 vs 用户轮次折叠态是两层独立机制
- 遮蔽段不可展开查看原文（已从模型上下文移除）
- 视觉区分：遮蔽段用虚线边框 + 浅灰，用户轮次折叠用实线 + 中灰

---

#### 方案 B：斜线纹理 + 内联摘要

**表现**：
- 被遮蔽的节点填充斜线纹理（`pattern` SVG fill）
- 不折叠，保持节点原有大小和位置
- 节点下方显示内联摘要：`[遮蔽] 3 条 · "用户问了..."`
- 视觉上像「被划掉」的感觉

**与现有折叠共存**：
- 遮蔽态是独立的视觉状态，不与折叠态冲突
- 遮蔽段不可展开（原文已移除）
- 视觉区分：遮蔽 = 斜线纹理，折叠 = 圆形摘要节点

---

#### 方案 C：收缩为胶囊 + 时间线标记

**表现**：
- 被遮蔽的整个分支段收缩为一个「时间线标记」（类似 Git 的 squash commit）
- 标记显示：`▸ 3 条消息已遮蔽 · 点击查看摘要`
- 点击标记展开显示摘要（不展开原文）
- 时间线主干上用虚线 + 小三角标记遮蔽段位置

**与现有折叠共存**：
- 遮蔽段收缩后不再占用纵向空间
- 与用户轮次折叠完全独立（用户轮次折叠控制「是否显示细节」，遮蔽控制「是否可见」）
- 视觉区分：遮蔽收缩 = 虚线三角标记，用户轮次折叠 = 圆形摘要节点

---

### 推荐：方案 A（灰显 + 折叠为摘要节点）

**理由**：
1. **与现有折叠机制一致**：复用 turn-summary 的视觉模式，用户认知成本最低
2. **空间效率**：折叠后不占用纵向空间，图谱保持紧凑
3. **视觉区分清晰**：灰显 + 虚线边框 vs 现有折叠的实线 + 中灰，一眼可辨
4. **摘要信息充足**：条数 + 首尾缩略足够理解上下文

**实现要点**：
- 摘要节点样式：`stroke-dasharray: 4 3` + `opacity: 0.6` + 浅灰填充
- 摘要内容：`N 条消息 · "首条缩略...末条缩略"`
- 悬停 tooltip：显示完整摘要 + 「已被遮蔽」提示
- 不可展开（原文已从模型上下文移除）

## 设计任务 3：多跳累积管理

**场景**：用户多次切枝后，图谱上存在多个遮蔽段。

### 候选方案

#### 方案 A：全部显示，时间线标记

**表现**：
- 每个遮蔽段都显示为独立的摘要节点
- 时间线主干上用不同颜色/纹理区分各个遮蔽段
- 点击摘要节点展开查看该段摘要

**优点**：
- 完整保留历史信息，用户可追溯所有切枝操作
- 视觉上清晰展示「会话发展路径」

**缺点**：
- 多次切枝后图谱可能变得拥挤
- 纵向空间消耗大

---

#### 方案 B：只显示最新 N 个，旧的收起

**表现**：
- 只显示最近 3 个遮蔽段的摘要节点
- 更早的遮蔽段收起为「历史摘要」标记（一个可点击的节点）
- 点击「历史摘要」展开显示所有旧遮蔽段列表

**优点**：
- 空间效率高，图谱保持紧凑
- 最近的操作清晰可见，旧操作不干扰

**缺点**：
- 需要额外的「历史摘要」UI 元素
- 用户可能误以为旧遮蔽段被删除

---

#### 方案 C：侧边栏时间线标记（与 SlimOverlay 整合）

**表现**：
- 主图谱只显示当前活跃分支 + 最近 1 个遮蔽段
- SlimOverlay（收起窄条）上用特殊标记显示所有遮蔽段位置
- 点击窄条标记跳转到对应遮蔽段摘要

**优点**：
- 主图谱保持简洁，不被历史遮蔽段干扰
- 复用现有 SlimOverlay，不增加新 UI 元素
- 窄条天然适合显示时间线标记

**缺点**：
- 需要同时维护主图谱和窄条的状态同步
- 用户需要理解「主图谱 + 窄条」的双层信息

---

### 推荐：方案 A（全部显示，时间线标记）

**理由**：
1. **实现最简**：复用现有摘要节点渲染逻辑，无需额外 UI 元素
2. **信息完整**：所有遮蔽段都可见，用户可追溯完整操作历史
3. **空间可控**：折叠后每个遮蔽段只占一个摘要节点的高度，多次切枝不会过度拥挤
4. **与设计任务 2 一致**：推荐的方案 A（灰显 + 折叠为摘要节点）天然支持多段累积

**实现要点**：
- 每个遮蔽段独立渲染为摘要节点
- 摘要节点按时间顺序排列，最新在最下方
- 鼠标悬停显示 tooltip：「该段在 X:XX 被遮蔽」
- 点击摘要节点：定位跳转到该遮蔽段的起始位置（不展开原文）

## 设计任务 4：完整演示路径剧本

### 剧本 1：基础切枝流程

**步骤 1：新会话启动**
- 用户打开 SessionGraph 插件
- 图谱为空，显示「暂无节点——发条消息试试」
- 聊天区正常显示输入框

**步骤 2：发送第一条消息**
- 用户：「帮我分析这段代码」
- 图谱实时长出节点：
  - USER 节点（灰色圆，r=16）
  - 助手开始思考（暂无节点，等回复完成）
- 聊天区显示用户消息

**步骤 3：助手回复**
- 助手：「好的，我来分析...」
- 图谱长出：
  - ASST 节点（深灰圆，r=9+）
  - 金环闪烁（cursor 移动到新节点）
- 聊天区显示助手回复

**步骤 4：继续对话 2-3 轮**
- 用户：「再解释一下这个函数」
- 图谱继续生长，节点垂直排列
- 早期轮次自动折叠（FOLD_KEEP=2，最近 2 轮展开）
- 折叠的轮次显示为摘要节点：「用户消息... · 3 条」

**步骤 5：点击历史节点**
- 用户点击第 1 轮的 USER 节点
- **现状行为**：节点金环闪烁，聊天区滚动到对应消息（scrollToKey）
- **T5 新行为**：
  - 节点金环闪烁（保留）
  - 聊天区滚动到对应消息（保留）
  - 节点旁弹出确认气泡：「切到这里继续 ✕」

**步骤 6：确认切枝**
- 用户点击气泡中的「切到这里继续」
- **B1 执行**：
  - 第 2-3 轮的消息被标记为「被放弃分支」
  - compaction 式 replace 遮蔽这些消息（不进模型上下文）
  - 图谱上这些节点变为「遮蔽态」：灰显 + 虚线边框 + 折叠为摘要节点
  - 摘要内容：「2 条消息 · "再解释一下..." / "好的，我来...」
- **游标移动**：activeCursor 移动到第 1 轮节点
- **图谱高亮**：当前路径（第 1 轮及之前）节点 opacity=1，遮蔽段 opacity=0.6

**步骤 7：继续对话**
- 用户：「换个方向，讲讲性能优化」
- 图谱从第 1 轮节点后长出新节点（新分支）
- 遮蔽段保持折叠态，不干扰新分支显示
- 聊天区正常显示新对话

### 剧本 2：多次切枝 + 遮蔽段累积

**步骤 1-4**：同剧本 1

**步骤 5：第一次切枝**
- 点击第 1 轮节点 → 确认切枝
- 第 2-3 轮被遮蔽（摘要节点 A）

**步骤 6：继续对话**
- 用户：「换个方向」
- 从第 1 轮后长出新分支（第 4-5 轮）

**步骤 7：第二次切枝**
- 用户点击第 4 轮节点 → 确认切枝
- 第 5 轮被遮蔽（摘要节点 B）
- 图谱上同时显示：
  - 摘要节点 A（第 2-3 轮遮蔽段）
  - 摘要节点 B（第 5 轮遮蔽段）
  - 当前活跃分支（第 4 轮后）

**步骤 8：查看历史遮蔽段**
- 用户悬停摘要节点 A → tooltip 显示「2 条消息 · "再解释一下..." / "好的，我来...」
- 用户点击摘要节点 A → 定位跳转到该遮蔽段起始位置（不展开原文）

### 剧本 3：收起窄条状态下的切枝

**步骤 1-4**：同剧本 1

**步骤 5：收起 details 列**
- 用户点击图谱右上角 ⟩ 按钮
- 图谱收起，右侧显示 SlimOverlay 窄条
- 窄条上显示所有节点的圆点（dotStyle）

**步骤 6：点击窄条圆点**
- 用户点击窄条上的某个圆点
- **现状行为**：聊天区跳转到对应消息
- **T5 新行为**：
  - 聊天区跳转到对应消息
  - 窄条上弹出确认气泡（简化版）：「切到这里继续」
  - 点击确认后执行切枝

**步骤 7：展开图谱查看遮蔽态**
- 用户点击窄条左上角 ⟨ 按钮
- 图谱展开，显示所有遮蔽段摘要节点

```
    ↓

```
