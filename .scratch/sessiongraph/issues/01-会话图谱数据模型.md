## Question

会话图谱的节点/边/游标如何建模与持久化?

**已确认的平台事实**(研究:`research-dsh-platform.md` + `docs/dsh-host-event-system-research.md`):
- 消息实时流唯一入口 = `session/event`(session, event);event.type ∈ {user/message, assistant/message, tool/result, assistant/chunk, turn/start|end, step/start|end, session/title, compaction/*, ...};每条事件自带 seq(会话内单调)+ time(epoch ms);消息有全局 UUID id
- **跨会话层系现成**:header 字段 parentSession/origin/delegationDepth 持久化;`traceSession`/`subagents.listChildren|listDescendants` 直接返回祖先+后代树;`SessionStore.fork` 创建分支子会话
- **会话内分支不存在**:DSH 会话 = 线性 append-only 日志,无 active 游标概念 → 用户要的 Pi /tree 式同会话换枝需插件自建 sidecar 会话图(方案 A,见 `design-tension-notes.md`)
- 持久化候选:`ctx.sessionProjections.register`(注册投影单元,框架订阅 session/event 增量维护状态,onChanged 推送)——"图状态"的理想宿主;或插件自建存储
- 压缩不删历史:shadowed/log-only 事件仍可读(与 T02 相关)

**要决策的**:
1. 节点模型:哪些事件成节点?必选:user/message、assistant/message、tool/result;候选:turn/start|end(回合边界)、assistant/chunk(排除,太密)、compaction/summary(压缩点)、agent 切换标记(subagent/start|end → 特殊节点)
2. 会话内 parentId 的确定规则(线性日志下 parent = 前一个节点;跳转后 = 游标,见 T02)
3. sidecar 图状态宿主:sessionProjections(推荐)vs 自建存储;游标(activeCursor)的表示与持久化
4. 冷启动重建:如何从会话日志重放构建图(增量 readFrom vs 全量 readSession)
5. 多会话隔离(每个会话一棵图,单会话树范围)

## Answer

(grilling 已定,2026-08,全部按推荐)
- Q1 节点模型:消息节点仅 user/message + assistant/message;tool/result 与 turn/start|end 折叠为节点元数据,不作独立节点;agent 切换节点 = subagent/start|end 与子会话首节点合并为一个节点,建父→子边
- Q2 parentId:线性日志下 parent = 日志前驱(跳转后 = 游标,归 02 号票)
- Q3 图状态宿主:sessionProjections,按 session.id 分区;游标 = 图状态内 activeCursor 字段
- Q4 冷启动重建:增量 readFrom 追平,无基线时 readSession 全量兜底
- Q5 多会话隔离:每会话一棵图;会话 dispose 保留图数据、仅清运行态
